# Contracts

The backbone of the system. Contracts are written **before** the code that
implements or consumes them, and they version independently from deployment.

| Kind | Location | Status |
| --- | --- | --- |
| Event schemas | `events/` | Phase 1 — envelope exists; domain events land with their features |
| WS projection protocols | `realtime/` | Phase 2 — board frames pinned with the Realtime Command Center (projections, not events) |
| OpenAPI (generated from the API) | `openapi/openapi.json` | regenerated by `make gen-api` after every contract change; feeds the orval-generated web client (ADR 0005) |

## Realtime projection protocols

`realtime/` holds versioned WebSocket **projection** protocols — the frames a
live surface pushes (e.g. `realtime/board.v1.json` for the Realtime Command
Center wall). A frame is a projection of facts that are already recorded
elsewhere, not a new fact: it never joins the event catalog, uses no
`event-envelope`, and is validated against its own schema instead of OpenAPI.
The event rules still hold — additive only within a version (a breaking change
means a new version file that old and new coexist against), and no sensitive
employee data beyond identifiers — plus one projection-specific rule: frames
carry full-row idempotent state (a duplicate push is harmless), because
delivery is transient and missed pushes are recovered by resyncing a snapshot.

## Rules

- Every event uses `events/common/event-envelope.v1.json`.
- Within a version, changes are additive only. A breaking change means a new
  version file; old and new coexist while consumers migrate.
- Consumers must ignore unknown fields (forward compatibility) and deduplicate
  on `event_id` (idempotency).
- Sensitive employee data never appears in a payload beyond identifiers.
- Schema linting in `make check` arrives with the first event producer
  (Phase 3) — until then, contracts are reviewed by hand.
